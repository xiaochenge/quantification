# 报错排查与解决方案（持续更新）

> 每次踩到坑，都往这里加一条：**现象 → 原因 → 解决 → 注意**。
> 新会话接手时先扫这一份，能避免重复踩坑。
> 最后更新：2026-09-23

## 1. 环境与启动

### 1.1 bash 脚本报 `MYSQL_VERSION: unbound variable`

- **现象**：跑 `scripts/setup-mysql.sh` 直接失败，提示变量未定义。
- **原因**：macOS 自带 bash 3.2 的老毛病——变量名后面紧跟全角字符（`（`、`，`）时，
  会把多字节字符当成变量名的一部分。
- **解决**：变量加大括号，如 `${MYSQL_VERSION}`。

### 1.2 Flyway 校验失败（checksum mismatch）

- **现象**：启动时报 migration checksum 不匹配。
- **原因**：改了**已经执行过**的迁移脚本。
- **解决**：设计期可以改 V1 并重置测试库；**schema 冻结后一律只加新脚本，不改旧的**。

### 1.3 改了 `application.yml` 但配置不生效

- **现象**：`spring.config.import` 加载的外置配置被 `application.yml` 里的空值覆盖。
- **原因**：profile 文档里的 `password: ${DB_PASSWORD:}` 会在优先级上盖掉外置文件的值。
- **解决**：把占位符从 `application.yml` 里删掉，密码只留外置文件；环境变量优先级本就高于配置文件。

## 2. Bitget 接口

### 2.1 `40008 请求时间戳过期`

- **现象**：私有接口返回 `{"code":"40008","msg":"请求时间戳过期"}`。
- **原因**：**重试时复用了旧的时间戳和签名**。签名里含时间戳，重试必须重新签名。
- **解决**：时间戳与签名在**每次尝试内部**生成（见 `BitgetPrivateClient.send`）。
- **注意**：任何"重试/重发"逻辑都要重新签名，不能复用。

### 2.2 `SSLHandshakeException: Remote host terminated the handshake` / `Connection reset`

- **现象**：`ResourceAccessException: I/O error on GET ...: Remote host terminated the handshake`。
- **原因**：网络抖动导致 TLS 握手被重置，属于**瞬时故障**。
- **解决**：对网络/IO 异常做指数退避重试（1s → 2s → 4s，最多 3 次），见 `bitget/HttpRetry`；
  **业务错误不重试**（参数错、余额不足、签名错，重试没有意义）。

### 2.3 用生产 Key 加 `paptrading: 1` 头不会切到模拟盘

- **现象**：以为加了头就在模拟盘，实际打在真实账户。
- **验证**：实测两次调用返回的权益几乎一致 → 头被忽略。
- **解决**：必须使用**模拟盘专用 API Key**（在模拟盘界面里创建）；实盘/模拟盘两套密钥分开配置。

### 2.4 `paptrading: 1` 对公开产品接口也生效

- **结论**：公开接口 `/api/v3/market/instruments` 加 `paptrading: 1` 头、**无需签名**即可返回模拟盘清单
  （实测 25 个 vs 实盘 515 个）。用它来判断"模拟盘支持哪些币"。

## 3. 下单

### 3.1 `40808 ... size checkBDScale error value=0.23329294 checkScale=6`

- **现象**：数量被拒，提示精度不符。
- **原因**：数量小数位超过交易对允许的位数（现货 6 位，账户余额却有 8 位）。
- **解决**：数量**向下取整**（floor）到 `quantityPrecision`。

### 3.2 四舍五入后报 `25202 余额不足`

- **现象**：精度修好了，但报余额不足。
- **原因**：**四舍五入后大于实际余额**（0.23329294 → 0.233293）。
- **解决**：卖单一律**向下取整**，绝不四舍五入。

### 3.3 平仓时只成交一条腿，造成实际亏损（2026-09-23 真实事故）

- **现象**：合约腿已平、现货腿因精度被拒 → 变成裸多头；期间行情下跌，产生真实亏损。
- **根因**：下单参数**临时查、甚至按错误的精度处理**。
- **解决**：
  1. 交易对规则（精度 / 最小最大 / 乘数）**定时同步落库**（`instrument` 表），下单时**从库里读**；
  2. 数量/价格一律按规则校验，不满足就**放弃下单**，而不是"试试看"；
  3. 任一时刻发现"只剩一条腿"，**优先消除裸露敞口**（立即市价补/撤），先保命再复盘。
- **注意**：这类事故的成本远高于"少赚一点"，所以宁可不下，也不留单边敞口。

### 3.4 市价单的隐性成本

- **实测**：用市价单完成一次开平仓，损耗约为名义的 **0.32%**，高于纯手续费模型的 0.195%，
  多出来的就是吃价差。
- **解决**：用 **FOK 限价单**（价格 = 对手价 ± 缓冲），要么全成、要么全不成，顺带把滑点兜住。

### 3.5 **API 返回 success ≠ 成交**（2026-09-23 真实事故）

- **现象**：日志显示两腿都"已提交"，但账户里**只有合约空头、没有现货** → 约 1.9 万 USDT 的裸空头。
- **根因**：代码只判断了"下单请求是否被受理"（接口返回 `code=00000`），**没有反查实际成交量**。
  现货腿的限价太紧，交易所按 IOC 规则**立即取消**，但接口依然返回 success。
- **解决**：
  1. 下单后**必须按 clientOid 反查订单**（`order-info`），取 `cumExecQty` 作为**实际成交量**；
  2. **反查结果必须打日志**（状态 / 委托量 / 成交量 / 均价），否则事后无法定位；
  3. 一腿成交、另一腿没成交 → 用**更宽的价格补那一腿**；补不上就**回退已成交的腿**；
  4. 只有"两腿实际成交量都 > 0"才算建仓成功。
- **注意**：这是最危险的一类 bug —— **日志说没问题，账户里却是裸敞口**。

### 3.6 为什么用 FOK 而不是 IOC

- **FOK**：要么全部成交、要么整笔取消，**不会出现"半仓"**，天然适合"两条腿必须等量"的对冲场景。
- **IOC**：允许部分成交、剩余撤销，容易造成两腿数量不齐。
- **限价缓冲**：限价 = 对手价 ± 缓冲（默认 1%）。**缓冲只是"能接受的最差价"，实际成交价仍是盘口价**，
  所以放宽缓冲几乎不增加成本，却能大幅提高成交率。
- **下单量**：两腿各自按盘口算"缓冲内可吃多少"，**取小**作为本次下单量，避免一腿吃得下、另一腿吃不下。

## 4. 策略与数据

### 4.1 决策出的币，模拟盘根本不能交易

- **现象**：决策日志列出 EVAA / SOON 这类币，但模拟盘不支持，下不了单。
- **根因**：`decideTarget` 只按净年化排序，**没有按"当前模式可交易"过滤**；过滤只发生在执行阶段，
  导致决策日志失真（显示要买，实际跳过）。
- **解决**：`watch_coin` 表存 `real_supported` / `demo_supported` 两个标记（同步时分别拉实盘与模拟盘清单），
  决策**和**执行都用同一份过滤后的名单。
- **注意**：**过滤器要用在决策处**，不能只在执行处——否则日志会骗人。

### 4.2 模拟盘支持范围（2026-09-23 实测）

- 现货 25 个、合约 45 个；**真实加密币的交集只有 BTC / ETH / DOGE / SOL**。
- 因此模拟盘只能验证"程序链路"，验证策略收益要靠自建 mock 跑完整候选池。

### 4.3 现货默认不计入保证金

- **现象**：`effEquity` 远小于 `accountEquity`（差掉整个现货市值）。
- **原因**：账户抵押品模式为 `custom`（仅 USDT/USDC），现货币种不计入保证金。
- **影响**：若实盘亦然，"现货全额 + 合约 1 倍"实际需要 **2 倍资金**，收益要打对折。
- **状态**：**待确认项**，上实盘前必须核实（详见 `docs/phase-2-strategy-design.md` 10.4）。

### 4.4 资金费率窗口

- **注意**：10 天窗口是"窗口内费率**正负累加**"，不是"连续 10 天为正"。
- **注意**：各币结算周期不同（实测 4h 居多），年化必须按各自周期折算。

## 5. 其他

### 5.1 密钥守卫误报空值

- **现象**：`application.yml` 里写 `password: ""` 导致构建被密钥守卫拦下。
- **解决**：守卫已修正——空值、`""`、`''`、`${...}` 占位符一律放行。

### 5.2 环境变量名踩坑（zsh）

- **现象**：shell 脚本里用变量 `path` 导致 `PATH` 被覆盖，后续命令全部"command not found"。
- **原因**：zsh 里 `path` 是 `PATH` 的特殊数组别名。
- **解决**：脚本里别用 `path`、`home` 这类名字。

### 5.3 Mac 休眠会让程序"冻结"（2026-09-24）

- **现象**：`pmset -g` 显示 `sleep 1`（关屏后允许自动休眠）、`displaysleep 30`（30 分钟关屏）。
  也就是说，**离开约 30 分钟后 Mac 会休眠**——当前没睡只是因为"屏幕亮着"这个断言在生效。
- **休眠后**：JVM 进程被冻结（不是被杀）——线程停止、定时任务暂停、网络断开；
  唤醒后继续跑，但**错过的定时任务不会补跑**（`fixedDelay` 不补偿）。
- **最危险的情况**：休眠卡在两条腿下单之间 → 单边敞口 + 程序冻结 → 回退逻辑要等唤醒才跑。
- **解决**：跑程序时套一层防休眠，**不需要改系统电源设置**：

  ```bash
  caffeinate -i ./mvnw spring-boot:run     # 程序还没起时
  caffeinate -i                            # 程序已在 IDEA 里跑时，单独开个终端挂着
  ```

  （`-i` 只防"系统空闲休眠"，屏幕照样会关，不影响程序。）
- **注意**：开发机按 AGENTS.md 的定位本来就不需要 24 小时开机；这一条只在"需要整晚跑测试"时用。
  将来服务器上要正式设置"关闭自动休眠"。
